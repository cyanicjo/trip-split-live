# 관리자 조회·CSV 작성 가이드 구현 및 검증

2026-09-30 기준. 기존 보안 보완 위에 기능을 추가했으며 운영에는 아직 배포하지 않았다.

## 구현 결과

- **관리자 조회:** Google 로그인 후 서버의 비공개 `admin_users`에 등록된 UUID만 전체 여행을 조회한다. 첫 로그인 자동 승격은 없다. 목록은 생성 시간·UUID 내림차순 커서로 50개씩 조회하며, 정렬 인덱스를 추가했다. 기존·신규·공유 링크가 폐기된 여행 모두 포함한다.
- **상세:** 참여자·은행·계좌·지출 품목·일정·외화·완료 송금과 남은 정산을 표시한다. 기존 앱과 정산 계산 모듈을 공유한다. 관리자 응답에는 편집 키·해시·보기 링크 식별자를 포함하지 않는다.
- **조회 전용:** authenticated 역할은 관리자 조회 함수 두 개만 실행할 수 있다. 여행 테이블·비밀 테이블·관리자 목록 직접 접근과 수정·삭제·링크 재발급은 거부한다. 일반 여행은 기존 링크 방식으로 유지한다.
- **인증·화면:** 공식 SDK 2.117.2를 고정해 자체 호스팅하고 PKCE를 사용한다. 인증 정보는 세션 저장소에만 저장한다. 관리자 내용은 영구 저장하지 않는다. 로그아웃·조회 오류·권한 거부·탭 숨김에 내용을 지운다. 늦게 도착한 응답이 내용을 되살리지 못하도록 요청 세대를 검사한다. 활성 탭은 30초마다 재확인한다.
- **CSV:** UTF-8 BOM 빈 양식과 가짜 작성 예시, 11개 열의 설명, 필수 항목, 빈칸 기본값, 품목 묶기, 중복 제외, 원화 한계를 안내한다. 미리보기의 행 수와 최종 지출 수를 구분하고 금액 열을 ‘단가(원)’로 표시한다.

## 위험과 검증 수준

| 항목 | 위험도/재현 조건 | 검증 수준·결과 |
|---|---|---|
| 관리자가 아닌 계정의 전체 조회 | 높음: 관리자 API 직접 호출 | 격리 PostgreSQL에서 anon·미식별·다른 계정 모두 거부 확인 |
| 관리자 자동 승격·자기 권한 부여 | 높음: 최초 로그인 또는 비공개 표 접근 | 자동 등록 없음, 계정 스스로 표 읽기·추가 불가 확인 |
| 등록 해제 후 기존 로그인으로 접근 | 높음: 동일 계정 UUID로 재요청 | 등록 해제 직후 목록·상세 모두 거부 확인 |
| 관리자 편집 우회 | 높음: 직접 수정·삭제·저장·재발급 요청 | authenticated 역할에서 모두 거부 확인 |
| 로그아웃 뒤 늦은 응답·악성 HTML | 중간: 지연 응답 또는 이름에 HTML 입력 | 실제 UI 코드/JSDOM에서 표시 복구 차단·안전한 텍스트 표시 확인 |
| 페이지 경계의 여행 누락·중복 | 기능 무결성: 생성 시간이 같은 행 | 가짜 여행 102개를 50/50/2로 중복 없이 조회 확인 |
| CSV 단가·품목별 정산 오류 | 기능 무결성: 여러 품목·일부 참여자 | 실제 가져오기 코드로 3개 품목→2건·36000원, 부담액 13000/13000/10000원 확인 |
| 운영 Google 로그인·실제 계정 승인 | 운영 설정 의존 | 미검증. SDK PKCE·세션 저장·Bearer 전달은 가짜 인증 응답으로 검증 |
| 운영 DB와 GitHub Pages 배포 | 운영 접근 필요 | 미적용·미검증. 로컬 결과를 운영 완료로 간주하지 않음 |

## 테스트 결과

프런트엔드 22개, 기존 DB 보안 58개, 관리자 DB 13개: 총 93개와 기존 정산·일정 테스트가 통과했다. 원본 로그는 `TEST_RESULTS.txt`에 있다. 의존성 감사 결과는 `dependency-audit.json`에 보관한다.

실제 브라우저와 격리 DB에서 관리자 목록·상세·계좌·일정·외화·정산을 확인했다. 가짜 CSV 예시를 선택하고 저장해 지출 2건이 추가되었고, 다른 관리자 탭에서 합계가 12000원에서 48000원으로 갱신되는 것을 확인했다. CSV 열 연결이 자동으로 맞춰졌으며 브라우저 오류 로그가 없었다. 관리자 브라우저 검증의 로그인은 로컬 인증 대역이며 운영 Google 인증을 대신하지 않는다.

## 설정과 남은 작업

`ADMIN_SETUP.ko.md`에 Google OAuth 콜백·정적 앱 배포·본인 UUID 등록·해제·관리자 기능 중지를 정리했다. SQL은 데이터를 보존하며 반복 적용 가능하다. 운영 전에는 본인이 실제 Google 계정에 로그인하고 그 계정을 등록해야 한다. 비밀 키를 브라우저 설정이나 저장소에 넣지 않는다.

같은 github.io 출처에서 실행되는 다른 코드가 세션 저장소에 영향을 줄 수 있다는 기존 정적 호스팅 한계는 남는다. 관리자 접근 기록 보관·개별 사용자 로그인·초대·추가 남용 방지 서비스는 이번 구현에 포함하지 않았다. 기존 보안 보고서의 링크 양도와 요청 남용 관련 제한도 유지된다.
